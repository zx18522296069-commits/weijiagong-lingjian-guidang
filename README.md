# 未加工零件自动归档系统

本项目在 GitHub Actions 云端执行，Mac 关机不影响运行。

## 当前正式业务口径

系统固定按下面顺序理解数据：

1. **“正在加工”订单目录**：当前订单范围。
2. **每个订单目录中的正式汇总表**：当前订单事实源；无法唯一确定时禁止猜测。
3. **《累计加工台账.xlsx》**：永久累计事实，保存累计状态、加工流水、板材入账记录和历史。
4. **《当前待加工零件.xlsx》**：动态视图，由当前订单事实 + 永久累计事实完整重建。
5. **“拆图结果”根目录完成文件**：本轮待处理板材；不扫描“已录入数量”子目录。

订单目录数量、可用订单汇总表数量、本次扫描板材数量是三个不同概念，日志和控制台不得互相混用。

## 订单源扫描

“正在加工”根目录中的订单文件夹/文件夹快捷方式都计入订单目录数量。

正式订单源支持：

- 文件名包含“汇总表”的 Excel；
- 若没有“汇总表”文件，则允许“模板”或“模版”Excel；
- 为兼容实际目录结构，只安全向下一层子文件夹寻找，不无限递归；
- 同一订单同一优先级出现多个候选时立即阻断，禁止自动猜测；
- 找不到正式汇总表的订单目录必须写日志提示，不能静默消失；
- 汇总表自身订单号与订单目录不一致时作为订单源异常处理，不得偷偷使用。

## 增量缓存

未变化的订单原始汇总表复用结构化缓存，只有新增、修改、重命名或移动导致签名变化时才重新下载解析。

缓存只是性能层，不是业务事实源。缓存丢失或损坏时必须回到真实 Google Drive 文件重新读取。

GitHub Actions 可以恢复生产缓存；**只有 production 且任务成功后才保存新的正式缓存**。dry-run、失败运行不得覆盖生产缓存。

## 板材处理规则

每次正式运行只扫描“拆图结果”根目录直接存在的 `*_完成.xlsx / xlsm / xls`。

每张板必须整板校验：任何应该阻断的行失败，则整张板不入账、不移动，文件继续留在根目录。

### 完整板材号与内容指纹

板材号保留完整标识，例如：

- `#2323`
- `#2323-1`
- `#2323-2`

规则：

- **完整板材号相同 + 内容指纹相同**：历史已经正式入账，禁止再次累计；当前文件只作为补归档候选，核验成功后移动到“拆图结果/已录入数量”。
- **完整板材号相同 + 内容指纹不同**：一律判定 `同板材号内容冲突`，不得当成另一张新板再次入账；写明原因并保留根目录等待人工核查。
- **完整板材号不同**：按独立板材分别处理。
- 早期历史记录没有内容指纹时，必须用当前文件、永久加工流水和板材入账记录重新核验；能够唯一证明一致才补归档，否则阻断。

## 阻断与超加工

以下属于阻断，例如：订单找不到、图号无法唯一匹配、厚度/坡口无法唯一确认、基础数量或基础总重量不一致、文件损坏、同板材号内容冲突等。

阻断板：

- 不累计；
- 不移动；
- 文件保留在“拆图结果”根目录；
- 控制台逐张显示原因和下一步。

如果基础身份和业务资料都正确，只是累计后 `当前剩余 < 0`，不作为阻断：

- 累计数量照实保留；
- 当前剩余允许负数；
- 状态为 `超加工/待核查`；
- 整行红色；
- 禁止自动把负数改成 0。

## 状态和颜色

统一使用：

- `未加工`：黄色
- `部分完成`：黄色
- `已完成`：绿色
- `超加工/待核查`：红色

不再使用“未开始”。

订单没有整体完成时，该订单区域完整保留，已经完成的零件也继续显示绿色“已完成”。只有订单所有零件 `当前剩余 == 0` 时，整个订单才从《当前待加工零件》退出；《累计加工台账》永久保留。

## 正式表写回保护

阻断异常本身不属于累计业务事实变化。若本轮只有阻断板、订单事实和累计事实均未变化，则跳过两份正式 Excel 上传，避免无意义重写。

真正发生下列变化时允许重建并写回：

- 当前订单事实变化；
- 累计已加工变化；
- 加工流水变化；
- 板材入账记录变化；
- 正式状态规范化（例如历史“未开始”迁移为“未加工”）。

新入账文件和补归档文件只有在正式台账验证通过以后才能移动到“已录入数量”。

## 控制台结果口径

“未加工更新运行结果”只围绕**本次扫描板材**展示：

- 本次扫描 X 张
- 成功录入 Y 张
- 重复已处理 Z 张
- 未成功 N 张

必须满足：`Y + Z + N = X`。

订单目录数和订单源数只能作为订单源检查信息展示，绝不能当成板材扫描总数。

每张未成功板材必须显示：板材号、未录入状态、具体原因、下一步。

订单源缺失/内容错误单独作为“订单源/资料异常”提示，不得混入板材数量。

## 正式台账自愈

每次运行在“正在加工”根目录按正式文件名重新发现：

- `累计加工台账.xlsx`
- `当前待加工零件.xlsx`

若文件被删除，程序按现有自愈逻辑尝试重建；若订单源存在不可读取或不完整情况，则阻断重建，禁止用缺订单的数据生成正式台账。同名正式文件出现多个时同样阻断。

## 定时与触发

本仓库自身不维护固定业务 cron。

- 前端立即执行：生产控制台通过 GitHub API `workflow_dispatch` 触发 production。
- 前端定时执行：由生产控制台保存的北京时间计划触发 `workflow_dispatch`。
- GitHub 页面人工执行默认 `test`，属于 dry-run / 只读测试；需要正式补跑时显式选择 `production`。
- 自动执行时间只在生产控制台维护，禁止再建立第二套业务时间。
