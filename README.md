# 未加工零件自动归档系统

本项目已将未加工零件统计流程迁移到 GitHub Actions 云端执行，Mac 关机不影响运行。

## 目标功能

- Google Drive 自动读取订单数据
- 拆图结果自动识别
- 按板材编号累计加工数量
- 保留“废”字作为独立编号
- 防止重复录入
- 自动更新：
  - 当前待加工零件.xlsx
  - 累计加工台账.xlsx
- 自动归档已录入完成文件
- 自动生成执行日志

## 正式台账自愈规则

每次运行都在“正在加工”根目录按正式文件名重新发现：

- `累计加工台账.xlsx`
- `当前待加工零件.xlsx`

不再依赖历史固定 file ID。若文件被删除并重新生成，后续运行会使用新文件的真实 Drive ID。

- 两份文件都存在：按现有正式流程更新。
- 仅《当前待加工零件.xlsx》缺失：根据当前全部订单源 + 现有累计台账重新生成。
- 《累计加工台账.xlsx》缺失：根据“正在加工”全部当前订单重新建立累计台账基线，累计已加工从 0 开始、当前剩余=订单原始数量，加工流水/板材入账/异常历史为空；本次“拆图结果”根目录中的完成文件仍按正常规则继续核验并计入。
- 两份都缺失：按上述基线一次性重新生成两份正式表。
- 新建文件必须写回“正在加工”根目录，格式、工作表、字段、颜色和布局继续使用当前正式 Excel 生成器，不另造模板。
- 若重建时存在任一订单原始汇总表无法读取，整次重建阻断，禁止用不完整订单集合生成正式表。
- 若“正在加工”中出现两个同名正式表，整次运行阻断，禁止自动猜测使用哪一份。

## 增量更新规则

“正在加工”中的订单原始汇总表不再每次全量下载、全量解析。

每次运行先读取 Google Drive 文件元数据，并按以下组合判断订单源是否变化：

- Drive file id
- `modifiedTime`
- 文件大小
- 文件名
- 订单目录名

未发生变化的订单直接复用上一次已经验证过的结构化解析缓存，不重新下载、不重新解析 Excel；只有新增、修改、重命名或移动后导致签名变化的订单，才重新下载并解析。

Drive 文件体也使用持久化缓存：相同 file id + `modifiedTime` + size 时直接复用缓存。程序正式写回《累计加工台账》和《当前待加工零件》前会主动清掉这两个正式文件的旧缓存，所以写回后的回读验证仍然真实从 Google Drive 重新下载，不允许用缓存代替远端验证。

缓存只是加速层，不是事实源。缓存丢失或失效时系统会自动回到真实 Google Drive 文件重新读取；业务规则和核对标准不因缓存改变。

## 定时与触发方式

本项目不自行设置固定 GitHub Actions cron 定时。正式自动执行时间由生产控制台前端定时配置统一管理；本仓库仅负责接收触发并执行未加工零件更新流程。

统一规则：

- 前端“未加工更新”立即执行：生产控制台通过 GitHub API `workflow_dispatch` 以 `production` 模式触发本仓库。
- 前端定时执行：生产控制台后台调度器读取前端保存的北京时间计划，到点后通过 GitHub API `workflow_dispatch` 触发本仓库。
- 本仓库 `.github/workflows/update_parts.yml` 不包含 `schedule`，不保存任何业务固定 cron。
- `workflow_dispatch` 同时保留给人工测试、dry-run、生产补跑和故障恢复使用；GitHub 页面人工执行默认 `test`，需要时可显式选择 `production`。
- 修改自动执行时间时，只修改生产控制台前端定时配置，不再修改本仓库 workflow。
- 禁止在 README、Python 脚本、其他 workflow 或其他后台服务中再维护第二套“未加工更新”业务时间。

## 订单建立与重复板材规则

- “正在加工”中的原始订单汇总表是当前订单的事实源。首次识别到、但尚未出现在两个正式 Excel 中的订单，系统会自动建立，初始累计已加工为 0。
- “当前待加工零件.xlsx”是动态视图，每次由当前订单源和累计结果完整重建；不作为历史去重依据。
- “累计加工台账.xlsx”保存永久加工流水和板材入账记录，是唯一的重复入账依据，不能手工清空。
- 板材号必须保留文件名中的完整标识，包括 `-1`、`-2` 等小序号；若完成文件因同名被系统命名为 `#2323_完成 (1).xlsx` 或 `#2323_完成（1）.xlsx`，括号序号也视为小号，统一记为 `#2323-1`。该完整标识会写入台账、加工流水、异常记录及零件加工来源。
- 每次正式运行都会扫描“拆图结果”根目录。若“完整板材号 + 内容指纹”已在累计台账中，判定为已入账但未归档：不录入、不扣减；两个正式 Excel 写回并回读验证通过后，直接移动到“拆图结果/已录入数量”。
- 对早期台账中没有内容指纹的记录，系统会用当前完成文件重新核对原始订单、加工流水和已入账件数；三项一致时，同样只补归档、不重复累计（例如 #2330_完成.xlsm）。
- 同一基础板材号但内容不同，视为不同板材，分别校验、分别入账；内容无法与已入账记录核对一致时，保留在根目录并阻断，绝不自动归档。

## Google Drive 凭据

个人网盘写入推荐使用用户 OAuth，两个自动化仓库配置同一组三项 Actions secrets：

- `GOOGLE_OAUTH_CLIENT_ID`
- `GOOGLE_OAUTH_CLIENT_SECRET`
- `GOOGLE_OAUTH_REFRESH_TOKEN`

三项齐全时程序优先使用 OAuth；未设置时兼容原 `GOOGLE_SERVICE_ACCOUNT_JSON`。服务账号没有个人 Drive 存储额度，因此只能把它作为 Shared Drive 或只更新既有文件的后备方式。
