# 未加工零件自动归档系统

本项目已将未加工零件统计流程迁移到 GitHub Actions 云端执行，Mac 关机不影响运行。

## 目标功能

- Google Drive 自动读取订单数据
- 拆图结果自动识别
- 按板材编号累计加工数量
- 保留“废”字作为独立编号
- 防止重复录入
- 自动更新：
  - 当前待加工零件.xlsx
  - 累计加工台账.xlsx
- 自动归档已录入完成文件
- 自动生成执行日志

## 执行方式

本仓库不再保存固定执行时间，也不维护独立定时规则。

统一规则：

- 手动执行：由生产自动化控制台前端“未加工更新”按钮触发；控制台按正式生产模式调用。
- 定时执行：仅由生产自动化控制台前端“定时设置”管理。控制台负责向本仓库工作流写入或移除 `schedule`。
- GitHub 仓库内直接手动运行仍保留 `workflow_dispatch`，默认 `test`，需要时可显式选择 `production`。
- 禁止同时在 README、脚本或其他工作流中维护第二套固定 cron，以免重复执行。

## 订单建立与重复板材规则

- “正在加工”中的原始订单汇总表是当前订单的事实源。首次识别到、但尚未出现在两个正式 Excel 中的订单，系统会自动建立，初始累计已加工为 0。
- “当前待加工零件.xlsx”是动态视图，每次由当前订单源和累计结果完整重建；不作为历史去重依据。
- “累计加工台账.xlsx”保存永久加工流水和板材入账记录，是唯一的重复入账依据，不能手工清空。
- 板材号必须保留文件名中的完整标识，包括 `-1`、`-2` 等小序号；若完成文件因同名被系统命名为 `#2323_完成 (1).xlsx` 或 `#2323_完成（1）.xlsx`，括号序号也视为小号，统一记为 `#2323-1`。该完整标识会写入台账、加工流水、异常记录及零件加工来源。
- 每次正式运行都会扫描“拆图结果”根目录。若“完整板材号 + 内容指纹”已在累计台账中，判定为已入账但未归档：不录入、不扣减；两个正式 Excel 写回并回读验证通过后，直接移动到“拆图结果/已录入数量”。
- 对早期台账中没有内容指纹的记录，系统会用当前完成文件重新核对原始订单、加工流水和已入账件数；三项一致时，同样只补归档、不重复累计（例如 #2330_完成.xlsm）。
- 同一基础板材号但内容不同，视为不同板材，分别校验、分别入账；内容无法与已入账记录核对一致时，保留在根目录并阻断，绝不自动归档。

## Google Drive 凭据

个人网盘写入推荐使用用户 OAuth，两个自动化仓库配置同一组三项 Actions secrets：

- `GOOGLE_OAUTH_CLIENT_ID`
- `GOOGLE_OAUTH_CLIENT_SECRET`
- `GOOGLE_OAUTH_REFRESH_TOKEN`

三项齐全时程序优先使用 OAuth；未设置时兼容原 `GOOGLE_SERVICE_ACCOUNT_JSON`。服务账号没有个人 Drive 存储额度，因此只能把它作为 Shared Drive 或只更新既有文件的后备方式。
